1. The Illusion of Zero-Downtime in Default Kubernetes

Many teams assume that deploying to Kubernetes automatically guarantees 100% uptime during rolling updates. In reality, terminating pods can abruptly drop hundreds of in-flight HTTP connections if your container does not handle SIGTERM gracefully or if your ingress controllers take several seconds to deregister endpoints.

Resilient Kubernetes Pod Manifest with PreStop Hook
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-service
spec:
  replicas: 4
  strategy:
    rollingUpdate:
      maxSurge: 25%
      maxUnavailable: 0
  template:
    spec:
      containers:
      - name: api
        image: registry.example.com/api:v2.4
        lifecycle:
          preStop:
            exec:
              command: ["/bin/sleep", "15"] # Gives ingress proxies time to stop routing traffic
        readinessProbe:
          httpGet:
            path: /healthz/ready
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 5

6. Post-Mortem: The Cascading 502 Bad Gateway Outage

During an automated deploy, an API service rebooted 10 pods simultaneously because maxUnavailable was set to 50% without a readiness probe. Inbound traffic hit non-ready containers, serving 502 errors to 40,000 active shoppers.

Fix: Enforced maxUnavailable: 0 and configured explicit Readiness Probes with an initial delay of 10 seconds.

7. Kubernetes Production Hardening Checklist

  • Set maxUnavailable: 0 in production rolling updates.
  • Always implement a preStop sleep hook (10-15s) to allow ingress propagation.
  • Define PodDisruptionBudgets (PDB) to survive node draining and cluster upgrades.
  • Run containers as non-root (runAsNonRoot: true) with read-only root filesystems.

1. وهم عدم الانقطاع الافتراضي في كوبرنتس

كوبرنتس لا يضمن عدم الانقطاع تلقائياً إلا إذا كان تطبيقك يستجيب لإشارة SIGTERM بسلاسة وتتأكد من أن مجسات الجاهزية تمنع تحويل الزوار لحاويات لم تكتمل تهيئتها بعد.

7. قائمة التحقق الإلزامية لبيئات الإنتاج في كوبرنتس

  • ضبط maxUnavailable: 0 لمنع إغلاق الحاويات النشطة قبل جاهزية الحاويات الجديدة.
  • استخدام preStop sleep hook لمنح خادم التوجيه وقتاً كافياً لإنهاء الاتصالات النشطة.
  • تحديد ميزانية PDB لحماية التطبيق من السقوط أثناء تحديثات السيرفرات.
