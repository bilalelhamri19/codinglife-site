1. Beyond Simple Message Queues: The Log Abstraction

Apache Kafka is not RabbitMQ or SQS. It is an append-only distributed commit log. Messages are ordered within partitions, immutable, and retained based on time or compaction policies. This fundamental architectural distinction enables event replayability, horizontal scaling, and zero-loss audit trails.

"In an event-driven architecture, events are facts that happened in the past. You cannot change history; you can only append new facts."

2. Partitioning Strategies & Consumer Scaling

The partition is the atomic unit of parallelism in Kafka. A consumer group cannot have more active consumers than the number of partitions in a topic. Choose partition keys strategically to guarantee message ordering for specific entities (e.g., userId or orderId) without creating hot-partition skews.

Transactional Producer with Idempotence
// Initializing idempotent transactional Kafka producer
const producer = kafka.producer({
  transactionalId: 'order-checkout-tx-producer',
  maxInFlightRequests: 1,
  idempotent: true
});

await producer.connect();
const transaction = await producer.transaction();
try {
  await transaction.send({
    topic: 'orders.created',
    messages: [{ key: order.id, value: JSON.stringify(order) }]
  });
  await transaction.commit();
} catch (err) {
  await transaction.abort();
  throw err;
}

3. The Saga Pattern for Distributed Transactions

In distributed microservices, two-phase commits (2PC) do not scale and introduce locking deadlocks. Instead, orchestrate transactions across services using the Saga Pattern with choreography or orchestration, backed by compensating transactions whenever downstream steps fail.

Key Takeaway: Always design consumer handlers to be strictly idempotent. Network retries mean duplicate messages are an inevitable reality of distributed computing.

كافكا ليس مجرد طابور رسائل تقليدي، بل هو سجل موزع غير قابل للتعديل (Distributed Commit Log). الأحداث المسجلة تمثل حقائق تاريخية لا يمكن تغييرها، مما يتيح إعادة تشغيل الأحداث وتوسيع نطاق القراءة لآلاف المستهلكين بالتوازي.

تنسيق العمليات بين الخدمات المصغرة يتطلب تطبيق نمط Saga مع تجهيز عمليات تعويضية (Compensating Actions) لعكس الخطوات في حال فشل أي خدمة في السلسلة.

Kafka est un journal d'événements immuable et distribué, offrant une capacité unique de rejeu et une scalabilité horizontale massive.

2. Stratégies de Partitionnement

Le partitionnement est l'unité atomique de parallélisme. Choisissez soigneusement vos clés de partition pour garantir l'ordre séquentiel sans créer de partition chaude.
