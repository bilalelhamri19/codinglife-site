1. The Zero-Trust API Paradigm

Traditional network perimeter security (firewalls, VPCs) is obsolete. Once an attacker breaches the perimeter or gains compromised developer credentials, flat networks allow unfettered lateral movement. Zero-Trust API architecture assumes the network is already compromised: every single incoming request must be cryptographically authenticated, authorized at the discrete object level, and strictly rate-limited regardless of origin.

"Never trust an incoming request simply because it originated behind your internal private subnet or load balancer."

2. Broken Object Level Authorization (BOLA/IDOR): The #1 API Killer

OWASP consistently ranks BOLA as the most widespread and damaging API vulnerability. BOLA occurs when an endpoint relies on a user-supplied ID (e.g., /api/documents/1042) to fetch a resource without verifying whether the authenticated user actually owns that resource.

TypeScript / Express — Vulnerable vs. Secure Object Authorization
// VULNERABLE TO BOLA / IDOR:
app.get('/api/invoices/:id', async (req, res) => {
  // Bug: Anyone with a valid JWT can view ANY user's invoice by guessing the ID!
  const invoice = await db.invoices.findById(req.params.id);
  res.json(invoice);
});

// ZERO-TRUST SECURE IMPLEMENTATION:
app.get('/api/invoices/:id', async (req, res) => {
  const currentUserId = req.user.id;
  const currentTenantId = req.user.tenantId;

  // Enforce ownership directly inside the SQL WHERE clause:
  const invoice = await db.invoices.findOne({
    where: {
      id: req.params.id,
      tenantId: currentTenantId, // Strict multi-tenant isolation
      userId: currentUserId
    }
  });

  if (!invoice) {
    // Return 404 instead of 403 to prevent resource existence enumeration!
    return res.status(404).json({ error: 'Invoice not found' });
  }

  res.json(invoice);
});

3. JWT Hardening: Algorithms, Revocation & Refresh Token Rotation

JSON Web Tokens (JWT) are frequently misconfigured. Production guidelines:

  • Strict Algorithm Whitelisting: Reject the "alg": "none" bypass and prevent RSA-to-HMAC algorithm confusion attacks by strictly configuring your verification library to accept only RS256 or EdDSA.
  • Short-Lived Access Tokens: Set access token TTL to a maximum of 15 minutes. Store access tokens in memory or strictly HttpOnly, SameSite cookies.
  • Refresh Token Rotation (RTR): Every time a client exchanges a refresh token for a new access token, invalidate the old refresh token and issue a new one. If an invalidated refresh token is ever reused, revoke the entire token family immediately (compromise detection).

4. Distributed Rate Limiting with Redis Sliding Windows

Standard fixed-window rate limiters permit 2x traffic bursts at window boundaries (e.g. 100 requests at 11:59:59 and 100 requests at 12:00:01). Production systems use a Sliding-Window Counter powered by Redis sorted sets (ZSET):

TypeScript / Redis — Sliding Window Rate Limiter
export async function checkRateLimit(ip: string, maxRequests = 60, windowSeconds = 60): Promise<boolean> {
  const now = Date.now();
  const windowStart = now - (windowSeconds * 1000);
  const key = 'rate_limit:' + ip;

  const multi = redis.multi();
  // Remove expired timestamps older than the sliding window
  multi.zremrangebyscore(key, 0, windowStart);
  // Add current request timestamp
  multi.zadd(key, now, now.toString());
  // Count requests within the current sliding window
  multi.zcard(key);
  // Set TTL on key to auto-clean memory
  multi.expire(key, windowSeconds);

  const results = await multi.exec();
  const requestCount = results[2][1] as number;

  return requestCount <= maxRequests;
}

5. Input Validation & Strict Schema Invariants with Zod

Never pass unvalidated user input into database queries or external API calls. Enforce strict Zod schemas that reject unexpected properties (strip unknowns) to block Mass Assignment attacks.

6. Production API Security Checklist

  • All endpoints enforce object-level ownership checks in database queries.
  • JWT signature verification explicitly whitelists RS256/Ed25519.
  • Distributed Redis sliding-window rate limiting enforced on all public routes.
  • Strict CORS headers configured; wildcard Access-Control-Allow-Origin: * banned.
